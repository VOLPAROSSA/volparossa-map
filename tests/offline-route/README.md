# Offline pedestrian routes on Android

This opt-in hosted trial runs the published Organic Maps Android app, in its original branding, in an Android 35 x86-64 emulator. Only the emulator namespace's loopback interface is available to the app and ADB. The real Monaco region and its two matching world files come from the public release catalog. All three full file SHA-256 hashes are checked before installation. The trial opens two public pedestrian routes through the app's ordinary URL handler after separate cold starts and reads the duration and distance from the native route UI.

Map data © [OpenStreetMap](https://www.openstreetmap.org/copyright) and [Organic Maps](https://organicmaps.app). The runner uses the original release under its [binary data license](https://github.com/organicmaps/organicmaps/blob/b20d1417eef1e3c63a447ac8658db4307a066024/DATA_LICENSE.txt). The artifact contains only measurements and the public input digests.

The traffic adapter and its signed peer trial run separately. This Android proof measures base-map routing without a traffic overlay.

The **Organic Maps source toolchains** workflow also builds the pinned upstream commit. Its Qt job registers the three original maps in a fresh profile, opens the normal desktop UI under Xvfb with software OpenGL, and checks two different native map frames before the application exits. Its Android job compiles the native x86-64 WebDebug APK and uses the same two-route emulator trial. Receipts identify the runtime, exact project and upstream revisions, and executable or APK digest. The uploaded artifacts contain measurements only.

For the Qt build containing the VOLPAROSSA traffic consumer, run `tests/native-toolchains/traffic_frames.py` twice under separate loopback-only Xvfb displays. Use modes `expiry` and `removal`, the same verified Core handoff bytes, and the publisher key and manifest ID from Core's independent publication receipt. Each run takes `--app`, `--upstream`, `--maps`, `--handoff`, `--publisher`, `--manifest` and a fresh private `--trial` directory. Start both while the advisory is fresh. Each records two Monaco views before the input is offered, after the native consumer accepts it and after the advisory disappears. The removal run deletes its own copy while it is still valid. The expiry run waits for its signed time boundary. Each compares saved Drape pixels, records frame measurements in `receipt.json` and closes the application through its ordinary Exit action.
